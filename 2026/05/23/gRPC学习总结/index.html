一、核心概念

1.1 什么是 gRPC

gRPC = Google Remote Procedure Call，就是”像调用本地函数一样调用远程服务”。底层用 HTTP/2 传输，用 Protobuf 序列化。

2.2 四种 RPC 模式

模式 proto 写法 特点 典型场景
简单 RPC rpc M(A) returns (B) 一问一答 登录、查询
服务端流 rpc M(A) returns (stream B) 客户端一问，服务端多答 导出数据、大列表
客户端流 rpc M(stream A) returns (B) 客户端多问，服务端一答 上传文件、批量导入
双向流 rpc M(stream A) returns (stream B) 两端独立收发 聊天、实时语音

5.2 四种调用方式

模式 客户端代码
简单 RPC resp, err := client.Method(ctx, req)
服务端流 stream, _ := client.Method(ctx, req) → for { msg, err := stream.Recv() }
客户端流 stream, _ := client.Method(ctx) → stream.Send(...) → resp, _ := stream.CloseAndRecv()
双向流 stream, _ := client.Method(ctx) → goroutine 收 + goroutine 发 → CloseSend()

六、关键知识点

6.1 context.Context（每个 RPC 的第一个参数）

作用 用法
超时控制 ctx, cancel := context.WithTimeout(context.Background(), 3*time.Second)
取消传播 ctx, cancel := context.WithCancel(...) → cancel() 中断调用链
元数据传递 metadata.NewOutgoingContext(ctx, md) → 服务端用 metadata.FromIncomingContext(ctx)

6.2 CallOption（每次调用的可选配置）

CallOption vs DialOption：

DialOption CallOption
设置时机 建立连接时 每次调用时
作用范围 整个连接 单次调用
举例 TLS 证书、拦截器 单次超时、响应头

6.3 UnimplementedXxxServer（安全兜底）

6.4 方法接收者（类似 this/self）

Go 没有 class，用 struct + 方法接收者 实现面向对象。

6.5 向后兼容的规则

七、从学习到生产的差距

学习阶段（route_guide 示例） 生产阶段（需要补充）
grpc.NewServer() + 拦截器（日志、限流、trace）
net.Listen + 优雅关机 GracefulStop()
insecure.NewCredentials() + TLS/mTLS 加密
硬编码 localhost:50051 + 服务发现（etcd/consul）
无健康检查 + grpc_health_v1 健康检查
无超时重试 + context.WithTimeout + retry policy
单实例 + 负载均衡（grpc.WithDefaultServiceConfig）

八、开发流程总结

gRPC 的核心思想：**.proto 文件是整个系统的唯一真相来源（single source of truth），服务端和客户端围绕它各自实现，互不干扰。**
